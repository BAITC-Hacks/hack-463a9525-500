# Граф денег

Локальный инструмент для проверки гипотез о финансовой структуре по обезличенным внутрибанковским переводам. Из 81 исходного gid строится сеть из 2 248 узлов. Пайплайн присваивает каждому узлу объяснимую роль, выделяет кластеры и формирует очередь проверки. Полноэкранный интерфейс на Next.js следует композиции приложенного дизайн-референса: оранжевое освещение, пять метрик, три аналитические панели, очередь проверки и график операций.

## Запуск одной командой

Требуются Python 3.10+, Node.js 20.9+ и npm. Для первой установки зависимостей нужен доступ к пакетным реестрам; сам анализ и интерфейс затем работают локально, без внешних API.

```bash
./run.sh
```

Откройте [http://127.0.0.1:3000/](http://127.0.0.1:3000/). Другой порт: `PORT=8765 ./run.sh`. Команда создаёт `.venv`, устанавливает зависимости, пересчитывает результаты из `data/*.parquet`, затем запускает Next.js на `127.0.0.1`.

Если нужен только пересчёт без интерфейса:

```bash
.venv/bin/python pipeline.py --data data --out out
```

Для проверки production-сборки: `npm run build`. При новом наборе с той же схемой замените три parquet-файла и запустите команду снова.

## Правила ролей

Правила применяются сверху вниз. Роль является **гипотезой для проверки**, а `role_score` показывает силу совпадения с её правилом, не вероятность противоправного поведения.

| Роль | Условие |
|---|---|
| `coordinator` | ≥3 разных плательщиков, ≥3 разных получателей, ≥2 исходных seed достигают узла по направленным путям длиной до 4, входящий поток ≥100 000 ₸ |
| `distributor` | ≥8 разных получателей и их число ≥1,5 числа плательщиков |
| `consolidator` | ≥4 разных плательщика и их число ≥1,5 числа получателей |
| `transit` | Не seed, есть входящие и исходящие связи; отношение отправленного к полученному в графе от 0,8 до 1,2 |
| `terminal` | Не seed, есть входящие связи, исходящих нет, глубина меньше 4 |
| `peripheral` | Остальные узлы, в том числе обрыв на 4-м колене и seed без наблюдаемых переводов |

Для транзита дополнительно показывается доля входящих операций, после которых **наблюдался любой исходящий перевод** в течение 0–2 дней. Это не связывает конкретный входящий платёж с исходящим и не используется как доказательство маршрута денег. Для seed отношение входящего и исходящего не применяется, потому что входящий поток seed неполон. Узлы на 4-м колене без исходящих не объявляются конечными получателями.

## Кластеры и приоритет

Кластеры считает Louvain с фиксированным `seed=42` на ненаправленной проекции графа, где вес пары равен сумме переводов в обе стороны. Направленный граф остаётся основой для ролей и визуализации. Одиночные узлы тоже получают `cluster_id`. Гипотеза по кластеру строится по преобладающей роли и не утверждает, что кластер является организованной группой.

`priority_score` находится в диапазоне 0–1 и складывается из: оборот 24%, число разных контрагентов 25%, взвешенный PageRank 20%, число исходных seed, достигающих узел, 17%, вес роли 14%. Непрерывные признаки нормируются логарифмически на 99-й процентиль. Вес роли: coordinator 1; consolidator 0,85; distributor 0,82; transit 0,72; terminal 0,50; peripheral 0,15. Список сортируется по этому числу. Высокий приоритет означает потребность в проверке, а не автоматическое решение о блокировке.

## Сценарий демо на 5 минут

1. Запустите `./run.sh` и покажите, что три CSV пересозданы.
2. На главной панели откройте строку очереди проверки. Карта по адресу `/network?gid=...` покажет входящих плательщиков слева и исходящих получателей справа, а карточка объяснит роль числами.
3. Введите произвольный gid в поиск на карте. Подсказки находят любой из 2 248 узлов, включая те, которых нет в обзорной выборке.
4. Переключитесь в режим «Обзор»: показаны 185 узлов с наибольшим приоритетом; фильтры позволяют выделить роль или один из крупных кластеров. Стрелки показывают направление перевода.
5. Откройте узел на границе 4-го колена: карточка помечает, что его исходящие переводы дальше не наблюдаются.

## Проверки и ограничения

- Перед расчётом пайплайн сверяет пары, суммы и число операций в `transactions.parquet` с `edges.parquet` и останавливается при расхождении.
- Набор содержит только внутрибанковские переводы за июль 2026, от 5 000 ₸, собранные по исходящим от seed на четыре колена. Переводы за пределами выгрузки неизвестны.
- `in_kzt` и `out_kzt` являются суммами **внутри графа**, не полным балансом клиента. Входящие seed занижены. На 4-м колене отсутствие исходящих означает границу обхода.
- У данных нет ФИО, ИИН, атрибутов клиента и размеченных истинных ролей. Интерфейс не выводит и не запрашивает персональные данные.
- Louvain может разделять большой связный фрагмент на несколько сообществ. Разбиение зависит от структуры и весов конкретного периода; идентификатор кластера не является постоянным идентификатором группы.
- Временной признак лишь отмечает близость дат входящих и исходящих операций, без восстановления трассы конкретных денег.

## Масштабирование до ~1 млн узлов

Для миллиона узлов текущие pandas/NetworkX и JSON со всеми связями на клиенте будут слишком затратны. Загрузка перейдёт на потоковое чтение Parquet по частям, метрики степеней и сумм на колоночные агрегации, PageRank и сообщества на графовый движок вроде igraph/GraphFrames, а интерфейс будет получать серверные выборки по кластеру и окрестности gid. Рассчитывать и хранить нужно только текущие снапшоты метрик и объяснений; полный граф отрисовывать на клиенте не следует. Критерии ролей останутся теми же, чтобы результаты можно было сверять между масштабами.

## Структура проекта

- `pipeline.py` — проверка данных, направленный граф, метрики, роли, кластеры и экспорты.
- `app/`, `components/`, `lib/` — Next.js App Router и интерактивная карта.
- `data/` — предоставленный обезличенный датасет и описание полей.
- `starter/` — неизменённый стартовый код организаторов для сравнения.
- `PRODUCT.md`, `DESIGN.md` — продуктовый и визуальный контекст по i-impeccable; исходный скриншот хранится в `docs/reference-dashboard.png`.
