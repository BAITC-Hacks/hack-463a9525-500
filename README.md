# MoneyGraph — Граф денег

Локальная система для исследования обезличенной сети переводов HackAlem AI. Она отвечает на вопрос: **какие из 2 248 счетов проверить первыми и почему?** Роли и приоритеты рассчитываются детерминированно. Любая роль — гипотеза для проверки, не обвинение и не вероятность вины.

## Запуск

Нужны Python 3.10+, Node.js 20.9+ и npm. Файлы `nodes.parquet`, `edges.parquet`, `transactions.parquet` находятся в `data/`.

```bash
./run.sh
```

Команда создаёт `.venv`, устанавливает зависимости, пересчитывает `outputs/`, запускает FastAPI на `http://127.0.0.1:8000` и Next.js на `http://127.0.0.1:3000`. Документация API доступна на `/docs` у порта 8000. Порты задаются через `PORT` и `API_PORT`.

Отдельные команды после установки зависимостей:

```bash
.venv/bin/python pipeline.py --data data --out outputs
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
npm run dev -- --port 3000
```

Последние две команды запускаются в разных терминалах. Начальная установка: `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements.txt`, `npm ci`. Проверки: `.venv/bin/python -m pytest -q` и `npm run build`.

### OpenAI в AI Analyst

Для реальных ответов через OpenAI создайте файл `.env.local` в корне проекта:

```dotenv
MONEYGRAPH_OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-6-luna
```

После этого перезапустите `./run.sh`. Ключ используется FastAPI и не передаётся браузеру. В запрос OpenAI передаются вопрос и относящиеся к нему рассчитанные показатели и связи, а не весь набор переводов. Без ключа чат явно показывает, что OpenAI не подключён; при ошибке API сообщает о сбое. Модель можно сменить через `OPENAI_MODEL`. Не добавляйте `.env.local` в Git.

Интерфейс использует TypeScript, Tailwind CSS v4 и структуру shadcn/ui. Компоненты лежат в `components/ui`, глобальные стили в `app/globals.css`, пути заданы в `components.json`; новые shadcn-компоненты добавляются командой `npx shadcn@latest add <name>`. Папка `components/ui` важна для корректной работы настроенного алиаса `@/components/ui` и CLI.

## Архитектура и результаты

```text
data/*.parquet → pipeline.py → outputs/*.csv + dashboard.json
                                     ↓
                               FastAPI (backend/main.py)
                                     ↓
                         Next.js (app/, components/)
```

Пайплайн проверяет схему, уникальность GID и пар, концы связей, неотрицательность сумм и совпадение агрегированных связей с транзакциями. На предоставленном наборе расчёт занимает около секунды на текущей машине; предел кейса — менее пяти минут на обычном ноутбуке.

| Экспорт | Содержание |
|---|---|
| `outputs/nodes_roles.csv` | По строке на GID: роль, `role_score`, кластер, `priority_score`, объяснение, графовые и временные признаки |
| `outputs/clusters.csv` | Размер, seed, внутренний и внешний поток, топ GID, распределение ролей и гипотеза |
| `outputs/top_nodes.csv` | Первые 50 узлов по приоритету с причиной |
| `outputs/dashboard.json` | Снимок для API и интерфейса; 18-значные GID сериализованы строками |

`starter/` сохранён для сравнения с исходным кодом организаторов.

## Методика

Направленный взвешенный граф сохраняет плательщика, получателя, сумму и число операций. Признаки включают степени, суммы, число операций, среднюю/медианную/максимальную операцию, PageRank, взвешенный PageRank, приближённое посредничество на 160 источниках (`seed=42`), слабую компоненту, число достижимых seed, связи с другими кластерами и процентили внутри глубины. Сообщества выделяются Louvain на ненаправленной взвешенной проекции (`seed=42`); роли и пути используют исходное направление.

Из транзакций извлекаются активные дни, даты первой/последней операции, частота, разброс дневного объёма и числа операций, всплески и доля входящих переводов, за которыми в течение двух дней есть исходящий перевод похожей суммы (±25%). Это **возможный быстрый транзитный паттерн**, а не доказанная трасса денег. Наблюдаемое отношение исходящего к входящему не является полным балансом.

Положительные величины переводятся в ранги от 0 до 1. Для каждой роли считается непрерывная оценка:

| Роль | Формула | Допустимость |
|---|---|---|
| `consolidator` | 35% входящая степень + 30% входящий объём + 20% разнообразие плательщиков + 15% доля входящих связей | ≥3 плательщика, входящих связей не меньше исходящих |
| `distributor` | 35% исходящая степень + 30% исходящий объём + 20% разнообразие получателей + 15% доля исходящих связей | ≥3 получателя, исходящих связей не меньше входящих |
| `transit` | 32% баланс вход/выход + 28% похожие суммы за ≤2 дня + 20% любой быстрый выход + 20% меньший ранг объёма двух направлений | Не seed; видны оба направления; отношение 0,55–1,6; есть временное совпадение |
| `terminal` | 40% входящий объём + 25% входящая степень + 35% отсутствие исходящих | Не seed; глубина <4; есть входящие; нет исходящих |
| `coordinator` | 25% посредничество + 23% взвешенный PageRank + 20% мост между кластерами + 18% достижимость seed + 14% относительный объём | ≥2 входящих и исходящих; ≥2 seed в путях или связь с другим кластером |

Побеждает самая сильная допустимая роль при оценке ≥0,55; иначе назначается `peripheral`. `role_score` — сила совпадения со структурным профилем. `truncated_by_depth=true` для глубины 4 без исходящих; такой узел не получает `terminal` из-за границы наблюдения.

`priority_score` отдельно складывает: 18% значимость роли × силу роли, 14% взвешенный PageRank, 16% посредничество, 14% объём относительно глубины, 10% достижимость seed, 10% межкластерный мост, 8% быстрые похожие суммы, 10% статистическую необычность. Приоритет направляет работу аналитика и не может сам по себе служить основанием для блокировки.

## API и AI Analyst

Основные маршруты: `/api/overview`, `/api/graph` (роль, кластер, глубина, приоритет, лимит), `/api/nodes/{gid}`, `/api/top-nodes`, `/api/clusters`, `/api/clusters/{id}`, `/api/search?q=`, `/api/path?source=&target=`, `/api/resilience?remove_top=`, `/api/analyst` (POST). `/api/dashboard` выдаёт снимок интерфейсу. Карточка узла содержит соседей, важные рёбра, временные признаки и ограничения видимости.

AI Analyst собирает контекст из рассчитанного снимка для вопросов о GID, ролях, кластерах, общих получателях/отправителях, путях, мостах и недостающих данных. OpenAI формулирует ответ на основе выбранных фактов. Упомянутые GID открываются в графе. Классификацию выполняет только локальный пайплайн.

## Интерфейс и демо

- `/` — обзор в полноэкранной визуальной системе по референсу.
- `/network` — карта соседей выбранного счёта и всей сети, направленные связи, плавные масштаб и панорама на canvas, поиск GID (`⌘/Ctrl+K`), фильтры и карточка.
- `/priorities` — очередь проверки с поиском и фильтрами.
- `/clusters` — сообщества и переход к GID или кластеру.
- `/methodology` — формулы и ограничения для жюри и аналитика.
- `/analyst` — отдельное рабочее место AI Analyst с вопросами и ссылками на проверенные GID.

Сценарий: открыть топовый GID из очереди, сравнить входящих и исходящих соседей, показать обоснование; затем найти произвольный GID; включить фильтр глубины 4 и объяснить цензурирование; открыть кластер, задать вопрос AI Analyst, скачать CSV.

## Ограничения и масштабирование

Набор охватывает исходящий обход от 81 seed до четырёх колен за июль 2026. Переводы ниже 5 000 ₸, внешние входящие и дальнейшие исходящие на границе могут отсутствовать. Особенно неполным может быть входящий поток seed. Нет личных атрибутов и размеченной истины; оценить точность классификации по этим данным нельзя. Временное сходство не устанавливает происхождение конкретных денег.

Для ~1 млн узлов чтение Parquet следует разбить на части, степени считать колоночными агрегациями, центральность и сообщества — специализированным графовым движком, а API должен выдавать окрестности и кластеры вместо общего JSON. Текущий локальный NetworkX и полная загрузка рассчитаны на 2 248 узлов.
